# Codex 异步提问

Vibe 支持 Codex 在工作中发起的 `request_user_input_async`：新问题显示为弹窗，也可以点 **Later** 暂时收起，再从输入框上方的 **Answer questions** 打开。普通聊天、TUI 和窄屏使用同一组件；命令授权弹窗优先显示。

## 数据与回传

1. Codex App Server 的实时 `item/completed` 通知带有 `agentMessage`、`delivery: "async"` 和 `questions`。Vibe 保留原文，同时建立独立的待答记录。只有文本中的问句不会触发弹窗。
2. 无选项的问题使用文本框，有选项的问题提供单选与自定义答案。预选项不会自动提交。用户明确点击 **Send answers** 才发送。
3. 有活动轮次时，回答作为明确标注的用户文本，通过 `turn/steer`（`threadId`、`expectedTurnId`、`clientUserMessageId`）加入当前轮次，不中断生成，也不排在普通下一条请求后面。
4. 已无活动轮次，或原生接口明确拒绝本次 steer 时，答案加入已有的持久化 **Next requests** 队列。队列暂停时不会自动恢复；用户需要确认恢复。回答不是伪造的工具返回值。

协议按已安装的 Codex CLI **0.153.4** 实验性类型定义核对；活动轮次回传遵循 [OpenAI App Server 的 turn/steer 协议](https://learn.chatgpt.com/docs/app-server#steer-an-active-turn)。异步提问的 `questions` / `delivery` 字段属于版本相关扩展，后续 CLI 升级应重新核对。

## 生命周期和安全

- 待答表单保存于 `VIBE_HOME/agent-questions/`，文件名为会话 ID 的 SHA-256；目录默认 `0700`、文件 `0600`，原子替换。只向有权访问该会话的账号分发，并按原生会话 ID 隔离。
- 收到新问题即去重、保存，再通知浏览器；不扫描旧聊天、旧工具调用或原生历史来补建问题。因此升级**不会恢复以前遗漏的提问**。
- 新收到的待答问题可跨刷新、断线和 Vibe 重启保留。切换 agent 后失效，删除会话时删除。**Dismiss question** 只收起并标记问题，不生成虚假的用户回答。
- 发送前先保存提交状态。同一问题的并发提交会被拒绝；已经确认完成的相同提交可幂等确认。
- 原生 ACK 丢失、超时，或重启前处于发送中时，标记为 **uncertain**，保存已提交的答案供核对，绝不自动重发。用户须检查聊天并勾选明确确认后才能重试；重试仍有重复处理的可能。断线期间禁止提交。
- 表单最多 20 个问题、同时最多 20 组待答；问题总大小上限 64 KiB，答案总大小上限 256 KiB。超限、磁盘或权限错误明确反馈，不静默覆盖损坏的状态文件。
- 未提交的输入是浏览器组件内草稿，不能保证跨整页刷新保存；已经开始提交且结果未确认的输入才写入私有待答状态。答案确认后按普通用户消息留在会话中。

此功能只补齐上述 **Codex 异步提问**。普通 Markdown 问句、同步 `item/tool/requestUserInput`、MCP elicitation 不是同一协议，不应混称为已支持。

## 回归验证

`npm run typecheck` 与 `npm test` 覆盖：实时字段解析和完成事件去重、无历史回扫、原生 steer 参数、明确拒绝/未知 ACK、父子线程隔离、私有持久化与重启、账号和原生会话隔离、同问题并发提交、普通队列与暂停语义、磁盘失败、切换与删除。

浏览器联调应使用隔离的 `VIBE_HOME`、真实 WebSocket handler 与假 runner：验证普通/TUI 模式的文本/选项弹窗、延后/关闭、刷新与断线、运行中即时回答及空闲排队、提交失败保留输入、窄屏滚动。不能对用户的旧问题作补发测试。

2026-09-10 验证记录：typecheck、生产构建通过；全套 616 个测试通过（新增 26 个，0 失败、0 跳过）。Chromium / Firefox × 普通 / TUI 四组隔离浏览器联调通过，包含浅色/深色和 390 × 520 窄屏检查。原生协议测试使用可控的进程替身模拟 ACK、拒绝和超时；未向真实模型或用户旧会话发送测试问题/答案。
